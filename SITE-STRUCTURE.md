# Site Structure — mokaid.com

One site: the existing React SPA (`apps/web`) serves both the product app and all public
SEO pages on the apex domain. Public routes are **prerendered to static HTML post-build**
(`apps/web/scripts/prerender.mjs`, Playwright) so crawlers get full content, canonical,
JSON-LD, breadcrumbs, and OG/Twitter metadata — while users get the untouched React
experience (landing 3D scene included).

## Hub-and-spoke architecture

- **Pillar:** `/ai-employees` defines the category and links down to all 8 role pages and out
  to use cases, comparisons, glossary, and blog.
- **Spokes link up** to the pillar and sideways to siblings (related roles block, related
  comparisons block, recommended roles per use case).
- **Blog supports:** each post links to the pillar plus at least 2 money pages.
- **Global:** the marketing header (5 sections) and the shared footer ("Resources" column on
  every page, landing included) guarantee ≤2 clicks from home to any page.

## Page template anatomy (roles / use cases / comparisons)

1. Breadcrumbs (+ BreadcrumbList JSON-LD)
2. H1 with target keyword, intro paragraph
3. Quotable definition card (GEO)
4. Body sections (responsibilities / bottlenecks / side-by-side table)
5. FAQ (FAQPage JSON-LD)
6. Related-content grid (internal links)
7. CTA → /signup

## Implementation map (single source of truth per page family)

| Concern | File |
|---|---|
| Roles data | `apps/web/src/data/seo/roles.ts` |
| Use cases data | `apps/web/src/data/seo/useCases.ts` |
| Comparisons data | `apps/web/src/data/seo/comparisons.ts` |
| Glossary data | `apps/web/src/data/seo/glossary.ts` |
| Blog posts | `apps/web/src/content/blog/*.md` (parsed by `src/data/seo/blog.ts`) |
| Site constants + JSON-LD helpers | `apps/web/src/lib/seo.ts` |
| Per-page head metadata | `apps/web/src/lib/use-seo.ts` (`useSeo` hook) |
| Page components | `apps/web/src/pages/seo/*.tsx` |
| Shared layout (header/footer/FAQ/CTA) | `apps/web/src/components/seo/marketing-layout.tsx` |
| Routes | `apps/web/src/router.tsx` (`seoPages`) |
| Prerender + sitemap | `apps/web/scripts/prerender.mjs` |

Adding a role/use case/comparison = adding one object to the data file; the page, sitemap
entry, and related-content blocks update automatically at the next build (the prerender
script discovers routes by crawling internal links).

## Serving (nginx, `infra/docker/nginx.conf`)

- `www.mokaid.com/*` → 301 → `mokaid.com/*`
- Public routes: prerendered `<route>/index.html` served statically (`try_files $uri
  $uri/index.html /spa.html`); the SPA hydrates on load
- App routes (`/dashboard`, `/login`, …): fall back to `spa.html` (the untouched SPA shell)
- `robots.txt`, `sitemap.xml`, `llms.txt`: static with correct content types
